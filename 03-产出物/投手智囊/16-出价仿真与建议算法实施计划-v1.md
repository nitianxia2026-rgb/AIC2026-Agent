# 投手智囊 · 出价仿真与建议算法实施计划

> 版本：v1.0｜2026-09-14｜定位：合成竞价场景下的相对调价测试带推荐，不是已由真实广告账户训练的精准出价模型。

> 2026-09-17实现补充：实际接入版本为`bid-sim-v1.1`。在原局部测试带基础上，引入`当前出价÷KB-02同组P50成本锚点`，使当前价数值参与响应与成本计算。锚点是合成口径，不是平台底价或真实市场价；v1.1仅支持同单位的CPM/CPC出价，oCPM目标成本或CPA出价不进入仿真。完整参数见《出价仿真参数登记-v1》和校验报告。

## 1. 当前缺口和升级目标

现有 KB-03 对所有行业使用同一条 `share(r)=r²/(r²+1)` 曲线，成本倍数预设为“出价倍数×曝光倍数”。它能做单调性防错，但不能依据预算、当前消耗、CTR/CVR、目标和渠道给出差异化建议，容易重复“提价增加竞争力、但边际成本上升”。

升级目标：对多个候选调价档位做保守/基准/乐观仿真，加入预算封顶和风险惩罚，根据目标输出“建议测试带＋首测档＋停止条件”。没有必要输入时只追问或给定性框架。

## 2. MVP 支持范围

- 支持：信息流/开屏的 CPM 场景、搜索的 CPC 场景；五行业桶；曝光/点击/留资/下单目标。
- 条件支持：oCPM/CPA 只做回传条件和风险判断，不输出假装精确的绝对出价。
- 输出：相对当前出价的测试档，例如 `-10% / 当前 / +10% / +20% / +30%`，以及模拟曝光、点击、转化、花费、单位转化成本和预算耗尽风险。
- 不支持：真实平台竞价胜率承诺、实时流量预测、自动操作账户、跨平台统一“最佳出价”。

## 3. 输入与缺参规则

### 必需输入

| 字段 | 说明 | 缺失处理 |
|---|---|---|
| industry | 五行业桶 | 一轮追问 |
| ad_type | 信息流/开屏/搜索 | 先由节点2选择 |
| billing_type | CPM/CPC | v1.1仅支持与KB-02锚点同单位的口径；oCPM/CPA只作回传和风险判断 |
| objective | 曝光/点击/留资/下单 | 一轮追问 |
| daily_budget | 日预算，元 | 一轮追问 |
| current_bid | 当前出价，元 | 没有则只给“首轮测试框架”，不输出绝对测试带 |

### 强烈建议输入

`observation_hours`、`spend_so_far`、`impressions`、`clicks`、`conversions`、`target_conversions`、`tracking_ready`。有实际表现时才能判断“花不完/正常/提前耗尽”；没有则使用合成场景并提高不确定性惩罚。

## 4. 算法逻辑

### 4.1 区分两个概念

- 调价倍数 `k = candidate_bid / current_bid`，用于局部候选搜索；
- 市场相对倍数 `r = candidate_bid / reference_bid`，只有真实/可说明的参考价存在时才使用。

没有 `reference_bid` 时，绝不把当前出价冒充市场基准价。MVP 用以当前状态为 1.0 的局部合成响应曲线，只输出相对测试带。

### 4.2 候选档位

默认：`0.8、0.9、1.0、1.1、1.2、1.3、1.5` × 当前出价。低预算、当前已快速耗尽时移除 1.3/1.5；完全不消耗且审核/追踪/定向未排查时，先输出排查，不运行提价推荐。

### 4.3 合成局部响应

为“行业×广告形式”配置合成的 `alpha、beta、traffic_index`，统一记录来源为项目假设。局部响应规范化为当前档 1.0：

```text
share(k) = k^alpha / (k^alpha + beta)
relative_delivery(k) = share(k) / share(1)
```

`alpha` 控制调价敏感性，`beta` 控制饱和速度。参数差异只用于仿真压力测试，不能称作真实行业弹性；如果无法及时完成参数评审，可先按广告形式分组，不强造五行业差异。

### 4.4 预算封顶与漏斗

CPM 场景：

```text
estimated_cpm(k) = base_cpm × cost_factor(k)
traffic_impressions(k) = baseline_impressions × relative_delivery(k)
affordable_impressions(k) = daily_budget / estimated_cpm(k) × 1000
simulated_impressions(k) = min(traffic_impressions(k), affordable_impressions(k))
clicks(k) = simulated_impressions(k) × CTR
conversions(k) = clicks(k) × CVR
spend(k) = min(daily_budget, simulated_impressions(k) × estimated_cpm(k) / 1000)
```

CPC 场景：

```text
estimated_cpc(k) = base_cpc × cost_factor(k)
traffic_clicks(k) = baseline_clicks × relative_delivery(k)
affordable_clicks(k) = daily_budget / estimated_cpc(k)
simulated_clicks(k) = min(traffic_clicks(k), affordable_clicks(k))
conversions(k) = simulated_clicks(k) × CVR
spend(k) = min(daily_budget, simulated_clicks(k) × estimated_cpc(k))
```

CTR/CVR/基础成本取 KB-02 同一分组的 P25/P50/P75，生成：保守（成本高、率低）、基准（P50）、乐观（成本低、率高）三情景，禁止跨格拼接。

### 4.5 推荐评分

```text
score = 目标达成度
        + 有效增量收益
        - 单位成本恶化惩罚
        - 预算提前耗尽惩罚
        - 三情景不稳定惩罚
        - 缺失输入惩罚
```

不同目标使用不同主指标：曝光看有效曝光/CPM；点击看点击/CPC；留资/下单看转化/CPA。权重是项目设计参数，必须进入参数表和敏感性测试，不能藏在提示词里。

### 4.6 拒绝推荐条件

- 缺当前出价或日预算；计费方式不明；转化目标但回传未确认；审核异常；隐私/合规风险；输入单位冲突；三情景结论方向相反且差异过大。
- 拒绝时输出“还缺什么、后台查哪里、补齐后怎么算”，不回退到固定的提价话术。

## 6. 真实数据是否需要、如何使用

### 复赛 MVP

不要求真实数据才能运行，但必须标“合成场景仿真”。公开数据主要用于方法和字段验证，不能直接校准五行业价格：

- AuctionNet：<https://github.com/alimama-tech/AuctionNet>，用于竞价、胜出、成本的逻辑参考；不直接搬数值。
- Criteo Sponsored Search Conversion Logs：<https://ailab.criteo.com/criteo-sponsored-search-conversion-log-dataset/>，用于搜索曝光/点击/转化事件链路和字段参考。
- Criteo Attribution Modeling for Bidding：<https://go.criteo.net/criteo-research-attribution-dataset.zip>，用于归因和反事实评估方法；不生成行业 CPM/CVR。
- Criteo 资源总页：<https://ailab.criteo.com/ressources/>，作为官方来源和条款入口。

### 最有价值的真实校准数据

如果团队已有合法、脱敏的广告账户历史导出，可用“计划×日期×调价阶段”聚合数据校准；不要为了比赛临时花钱投放，也不要收集用户级记录。最低字段：平台、行业桶、广告形式、计费方式、日期、观察小时、预算、当前出价、花费、曝光、点击、转化、审核状态、定向是否改变、素材是否改变。

只有同一计划在调价前后保持素材、人群、目标和观察窗口可比，才能用于响应校准。不得含手机号、设备 ID、Cookie 或用户明细。样本不足时只作为案例，不声称训练完成。

## 7. 脚本和产出

1. `bid_simulator.py`：读取 KB-02 参数和算法参数，生成候选档三情景模拟表及建议测试带。
2. `verify_bid_simulator.py`：检查固定种子可复现、单位、预算封顶、同条件单调性、成本/曝光边界、缺参拒绝、跨口径禁止和差异化。
3. 可选 `calibrate_bid_response.py`：仅在真实脱敏聚合数据达到最低门槛后拟合/比较局部响应；未达到时不创建假校准结果。
4. 输出 `06/07/08` 三个文件，并由人工抽样手算至少 2 个场景。

## 8. KB 与提示词接入

### 新增知识库源稿

- KB-04：只放参数版本、候选测试带、三情景结果、字段和合成声明。
- 规则08：必需输入、候选搜索、评分、拒绝推荐、输出结构和回退逻辑。

### 节点5调整

原“出价提高，曝光只能增加”升级为：

1. 先确认计费方式、当前出价、预算、目标和可比条件；
2. 有具体当前出价时才枚举候选档；
3. 有实际消耗数据时判断预算封顶；没有则提高不确定性并声明合成场景；
4. 输出测试带、首测档、理由、观察指标和停止条件；
5. 参数不足或异常未排除时拒绝给绝对出价；
6. 具体数值来自 KB-04/计算器，不能让模型临场编权重或插值。

脚本未通过前不修改比赛主提示词；通过后生成 v0.3 候选并回归。

## 9. 算法验收题

至少验证：同一行业不同预算、同预算不同 CTR、同预算不同 CVR、同条件不同目标、同当前出价不同消耗速度、预算封顶前后、缺 current_bid、计费方式混用。验收要求：

- 该有差异的场景输出确有差异；
- 只改变无关文案不改变数值；
- 花费不超过预算；曝光/点击/转化不出现负数；
- 不把相对当前调价倍数说成相对市场基准倍数；
- 保守/基准/乐观顺序合理；
- 所有拒绝条件命中；
- 输出统一声明“合成仿真，用于首轮测试，不代表平台最优出价”。
