# 投手智囊 · 复赛工具选择与评分对齐

> 版本：v1.3，2026-09-18。结论适用于复赛“助手”形态；总决赛工作流工具另行评估。

## 一、明确结论

复赛按平台当前实际能力配置：计算器、Web Research、值得买、可视化图表、思维导图作为正式能力。2026-09-16复核时平台没有Word/PDF导出和豆包多模态，因此从提示词、推荐问题和测试链中移除，不对用户承诺不存在的能力。

不为了工具数量添加空壳。自定义能力只保留一个候选：`bid_simulate` 出价仿真 API。当前`bid-api-v0.2`＋`bid-sim-v1.2`已完成零第三方依赖HTTP封装和OpenAPI契约，本地API 10/10、算法16/16通过；但尚未部署稳定公网HTTPS，也没有比赛网络与平台调用证据，因此仍是条件接入。平台截图已确认可直接粘贴/URL导入OpenAPI、选择API Key并逐项测试。普通REST接口不包装成MCP。

## 二、为什么计算器足够

1. 复赛平台是助手而非可视化工作流；核心流程必须写进系统提示词，工具通过明确触发条件补足“研究→分析→解释→交付”链路。评分不会因工具数量自动加分，关键是工具与节点的匹配、参数可用和演示稳定。
2. 本产品的核心计算仍由计算器完成；MCP 用于实时背景、竞品观察和可视化表达，不能替代知识库参数。
3. API 需要外部稳定HTTPS端点和OpenAPI Schema；平台支持直接粘贴/URL导入、API Key和逐工具测试。部署仍会引入网络、鉴权、超时和比赛环境不可用风险。
4. MCP 工具确有误调用风险，因此只添加已经实测且有清晰参数的工具，并规定一轮最多调用两类、失败必须降级。
5. 复赛 90 分钟内，先完成 P0 工具的正常/缺参/失败三类测试；未通过测试的工具不进入关键路径。

## 三、计算器的使用契约

- 计算器只做乘除、比例、汇总和单位换算，不决定参数来源。
- 参数先从 KB-基准库-02/03 读取，再把公式和参数交给计算器。
- 每个具体数字都要在【依据】段写出公式、参数分组和计算结果。
- 工具不可用时，不心算；降级为公式+参数区间或定性建议，并记录为平台问题。
- 测试集至少验证：正向漏斗、逆向预算、70/30 分配、出价倍数、百分比转小数。

| 工具 | 添加的具体函数 | 接入节点 | 触发问法 | 优先级 |

## 五、自定义 API / MCP 决策

### 复赛建议

| 方案 | 决策 | 原因 |
|---|---|---|
| 象征性自建MCP | 不做 | 平台已有同类能力，不能形成新的产品链路，反而增加超时风险 |
| 象征性API（回声、普通计算） | 不做 | 计算器已覆盖，无法证明业务价值 |
| 出价仿真API `bid_simulate` | v0.2本地完成，条件接入 | 能把团队算法变成真实工具节点；公网与平台验证未完成前不得计为已接入 |
| 把出价REST接口包装为MCP | 不做 | 官方要求SSE或HTTP/Streamable的真实MCP Server与`mcpServers`配置；重复包装不增加业务价值 |
| 离线KB-04接入 | 保底方案 | 无需部署，稳定；但展示时应说明是离线生成的算法结果库 |

`bid_simulate`只有满足以下条件才添加：HTTPS端点在比赛网络可访问；OpenAPI解析后只出现`POST /bid-simulate`；API Key不泄露；输入含行业、广告形式、计费方式、预算、当前出价、目标和消耗比例，留资/下单含回传状态；输出含候选档、首测档、观察/停止条件和合成声明；从比赛网络连续10次成功且平台端正常、缺参、失败三类测试均能正确降级。当前满足本地代码与契约测试，未满足公网和平台条件，因此继续保留KB-04兜底。

总决赛再考虑：

- 文件抽取：读取用户投放日志，前提是平台正式环境允许且完成隐私脱敏。
- 未来导出报告：若后续平台恢复可用工具，可把已生成的复盘结果导出 Word/PDF；当前复赛不接入，只交付可复制Markdown。
- 外部广告 API：当前不建议，涉及账号权限、实时数据和比赛环境风险。

任何新增工具都必须经过 A/B 对比：无工具、仅计算器、加入新工具三组，记录误调用率、响应时间、引用正确率；没有证据就不挂。

## 六、与评分项的映射

| 评分项 | 主要得分证据 | 工具作用 |
|---|---|---|
| 数据准备 10 | 真实/合成边界、字段字典、校验报告 | 无需 API/MCP |
| 知识库 20 | 7 份 SOP、3 份基准库、切片 QC | 计算器不替代知识库 |
| 提示词 30 | 六节点约束、引用纪律、红线和降级 | 明确计算器调用契约 |
| 架构 20 | 状态机、检索→计算→工具路由→输出链路 | 计算器和 MCP 作为受控执行节点 |
| 对话质量 10 | 正逆向计算、拒答、追问、口径隔离测试 | 记录实际调用和结果 |

## 七、最终配置

复赛建议配置：规则库＋基准库（按平台上限合并）＋系统提示词＋计算器＋Web Research＋值得买＋可视化＋思维导图。出价仿真优先以KB-04保底，稳定端点完成后再增加唯一的自定义API。

现场准备五条演示链：需求解析→方案卡；知识库→计算器漏斗；Web→最新政策；值得买→竞品差异化；图表/脑图→可视化解释。另以可复制Markdown报告展示交付完整度，但不算工具调用。
