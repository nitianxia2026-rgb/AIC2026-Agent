# 投手智囊 · 复赛工具选择与评分对齐

> 版本：v1.0，2026-09-12。结论适用于复赛“助手”形态；总决赛工作流工具另行评估。

## 一、明确结论

你的判断成立一半：工具丰富度能增强“实现架构”和应用完成度的观感，但不是越多越好。复赛建议添加 **4 类 MCP 能力**：Web Research、值得买、可视化图表、思维导图；内置计算器保留为必挂。导出 Word/PDF 和豆包文生图作为 P1 可选，不作为主流程依赖。API 暂不自写。

## 二、为什么计算器足够

1. 复赛平台是助手而非可视化工作流；核心流程必须写进系统提示词，工具通过明确触发条件补足“研究→分析→解释→交付”链路。评分不会因工具数量自动加分，关键是工具与节点的匹配、参数可用和演示稳定。
2. 本产品的核心计算仍由计算器完成；MCP 用于实时背景、竞品观察和可视化表达，不能替代知识库参数。
3. API 需要外部已部署端点和 OpenAPI Schema；临时自建端点会引入网络、鉴权、超时和比赛环境不可用风险。
4. MCP 工具确有误调用风险，因此只添加已经实测且有清晰参数的工具，并规定一轮最多调用两类、失败必须降级。
5. 复赛 90 分钟内，先完成 P0 工具的正常/缺参/失败三类测试；未通过测试的工具不进入关键路径。

## 三、计算器的使用契约

- 计算器只做乘除、比例、汇总和单位换算，不决定参数来源。
- 参数先从 KB-基准库-02/03 读取，再把公式和参数交给计算器。
- 每个具体数字都要在【依据】段写出公式、参数分组和计算结果。
- 工具不可用时，不心算；降级为公式+参数区间或定性建议，并记录为平台问题。
- 测试集至少验证：正向漏斗、逆向预算、70/30 分配、出价倍数、百分比转小数。

## 四、工具添加清单

| 工具 | 添加的具体函数 | 接入节点 | 触发问法 | 优先级 |
|---|---|---|---|---|
| Web Research | `webSearchPro` | 节点2/7 | 最新政策、平台规则、查竞品资料 | P0 |
| 值得买 | `product_search_list`、`content_summary_search`、必要时 `compare_price` | 节点6素材 brief | 竞品、卖点、价格带 | P0 |
| 可视化 | `generate_funnel_chart`、`generate_line_chart`、`generate_bar_chart` | 节点4/5/6 | 画漏斗、出价曲线、预算对比 | P0 |
| 思维导图 | `generate_mind_map`、`generate_flow_diagram` | 用户主动要求解释流程 | 画流程、做脑图 | P1 |
| 导出 | `markdown_to_document` | 收口后 | 下载方案、导出总结 | P1 |
| 豆包多模态 | `text_to_image` | 素材 brief 后 | 做广告概念图 | P1 |

参数、失败处理和示例见《平台工具能力记忆库》。

## 五、何时才考虑自建 API

仅在总决赛且满足“真实需求 + 外部端点稳定 + 已完成演练 + 有明确引用边界”时考虑：

- 文件抽取：读取用户投放日志，前提是平台正式环境允许且完成隐私脱敏。
- 导出报告：把已生成的复盘结果导出 Word/PDF，属于展示便利，不是核心评分能力。
- 外部广告 API：当前不建议，涉及账号权限、实时数据和比赛环境风险。

任何新增工具都必须经过 A/B 对比：无工具、仅计算器、加入新工具三组，记录误调用率、响应时间、引用正确率；没有证据就不挂。

## 六、与评分项的映射

| 评分项 | 主要得分证据 | 工具作用 |
|---|---|---|
| 数据准备 10 | 真实/合成边界、字段字典、校验报告 | 无需 API/MCP |
| 知识库 20 | 7 份 SOP、3 份基准库、切片 QC | 计算器不替代知识库 |
| 提示词 30 | 六节点约束、引用纪律、红线和降级 | 明确计算器调用契约 |
| 架构 20 | 状态机、检索→计算→工具路由→输出链路 | 计算器和 MCP 作为受控执行节点 |
| 对话质量 10 | 正逆向计算、拒答、追问、口径隔离测试 | 记录实际调用和结果 |

## 七、最终配置

复赛建议配置：规则库 + 基准库（按平台上限合并）+ 系统提示词（当前为 v0.1 工具路由增补稿，实测后冻结 v0.2）+ **内置计算器 + P0 的 Web Research/值得买/可视化**；P1 工具在通过测试且时间允许时加入。API 不接入。
