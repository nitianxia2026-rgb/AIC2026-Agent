# 投手智囊 · 复赛助手架构说明

> 版本：v0.3 候选实现，2026-09-17。复赛平台形态为“助手”，不是可视化工作流；意图路由和业务约束写入系统提示词，并由单一压缩知识库、计算器、受控工具和对话测试共同实现。当前系统提示词为 `v0.2-compact-candidate`，平台覆盖后再冻结。

## 1. 架构总览

```text
用户自然语言
  ↓
安全与隐私硬门
  ↓
唯一意图路由
  ├─ 整理/Markdown
  ├─ 竞品研究 ─────────────→ 商品工具
  ├─ 官方资料/平台入口 ─────→ Web Research
  ├─ 图表/流程/思维导图 ────→ 可视化工具
  ├─ 当前出价调整 ──────────→ KB-04/规则08 → 计算器
  ├─ 效果测算/预算反推 ──────→ KB-02 → 计算器
  └─ 起步投放方案 ──────────→ 规则库与必要追问
  ↓
事实、单位、来源与越界静默检查
  ↓
与任务匹配的短答案、结构化卡片、Markdown代码块或直显图片
```

完整投放方案或效果测算仍可按“需求解析→渠道/竞价→定向→数值预估→出价/预算自检→素材收口”展开；普通单点问题不强制走完六节点，避免无关扩写和缺参臆测。

## 2. 节点输入输出契约

| 路由/节点 | 输入 | 输出 | 主要依据 | 异常处理 |
|---|---|---|---|---|
| 安全硬门 | 用户原话 | 自然拒绝或继续路由 | 规则库07 | 不泄露内部规则，不给绕审替代路径 |
| 需求解析 | 起步方案/测算输入 | 行业、预算、目标及真正必要的缺口 | 规则库01 | 缺项最多一次问齐；不擅自默认 |
| 起步方案 | 行业、预算、目标 | 一个主平台、四个最小动作、一个必要追问 | 规则库02/03 | 不自动测算，不编平台组件或阈值 |
| 效果测算 | 预算或目标量、同组参数 | 曝光/点击/转化或逆向预算区间 | KB-02、计算器 | 缺参数、跨格或工具失败时停止数字输出 |
| 出价调整 | 行业、形式、计费、目标、预算、当前价 | 首测档、相邻带、观察与停止条件 | KB-04/规则08、计算器 | 单位冲突、缺参、审核/回传未就绪时拒绝绝对出价 |
| 官方资料 | 最新政策、入口或后台问题 | 标题、URL、用途、检索日期 | Web Research | 无法确认主体或链接有效时明确“未核验到” |
| 竞品研究 | 品类/型号/评价要求 | 每商品四字段卡 | 商品检索/评价工具 | 空结果不补造；无评价结果不写口碑 |
| 整理/Markdown | 当前会话已有事实 | 单个Markdown代码框 | 用户原文 | 无上文只请求粘贴，不调用搜索或计算 |
| 可视化 | 用户数据或已完成演算 | 直接显示图片 | 图表/流程/思维导图工具 | 无数据不作图；渲染失败给链接和文字版 |

## 3. 检索、计算和引用链

1. 规则类问题优先检索规则库；行情和演算参数只检索基准库。
2. 演算参数必须来自同一行业×广告形式×素材格；KB-01真实历史数据不能与KB-02合成参数混算。
3. 计算器只负责乘除、比例、汇总和单位换算；公式和参数必须先由知识库确定。
4. 输出数字时引用到文档、分组和字段；找不到字段就改为定性建议。
5. 所有区间标记“建议区间，非精确预测”；KB-02额外标记“按行业常见水平估算”。
6. 工具只在明确触发时调用；工具返回的实时信息不得覆盖知识库基准数字。

## 4. 状态转移与回推

- 正常路径：安全硬门→唯一意图路由→所需知识/工具→事实自检→匹配格式输出。
- 用户明确要求完整方案时，才在方案路由内部展开六节点；不相关节点可省略。
- 用户补充品类、预算或目标后重新解析，保留已确认字段，不擅自改变任务类型。
- 用户要求投后账户诊断、广告概念图生成或平台代投时，说明当前能力边界，不伪装已读取日志或执行账户操作。
- 一轮最多调用两类外部工具；工具缺参、空结果、冲突或超时必须降级，不能用模型常识补齐工具结果。

## 5. 复赛平台配置映射

| 产品设计 | 平台配置 |
|---|---|
| 安全硬门＋八类互斥意图路由 | 系统提示词流程约束 |
| 规则方法论 | 文档知识库，按层级切分 |
| 基准参数 | 文档知识库，合成/真实口径分开 |
| 算术计算 | 内置计算器 |
| 实时资料 | Web Research（仅外部背景，标注日期/URL） |
| 竞品观察 | 值得买 product_search_list/content_summary_search/compare_price |
| 解释性图表 | generate_funnel_chart / generate_line_chart / generate_bar_chart |
| 结构表达 | generate_mind_map / generate_flow_diagram |
| 文档交付 | 对话内生成可复制Markdown报告；当前无Word/PDF导出与广告文生图 |
| QA 语料 | 自然用户问法、失败样例和平台冒烟记录；不把诊断性约束题当产品验收 |
| 节点测试 | 对话测试集和人工验收表 |

复赛无可视化工作流，因此必须保存平台配置截图和测试记录，作为“实现架构”证据。新增 MCP 不是替代状态机，而是按触发条件挂接的工具路由层。

## 6. 架构验收标准

- 任一问题只命中一个主路由；单点问题不被扩写成六节点长方案。
- 缺少当前任务必填项时最多追问一轮；用户拒答时不给虚构数字或平台细节。
- 数字均可追溯；计算器调用可在平台记录或截图中证明。
- 无时段数据、跨库混算、固定预算曲线、敏感行业等负面场景均能降级或拒答。
- 出价仿真只支持同口径CPM/CPC，并固定声明“合成仿真，用于首轮测试，不代表平台最优出价”。
- 复赛版本不输出完整投后诊断、广告账户执行结果或广告概念图，不冒充真实广告素材。
- 工具调用不改变复赛范围：搜索和竞品仅作投前背景，数据图表、流程图和思维导图属于表达增强；Markdown报告属于文本交付能力。
