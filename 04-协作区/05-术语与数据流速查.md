# 第一部分 · 术语卡

## 1. 一条广告的一生（先读这节，后面全靠它）

老板娘花钱投广告，用户刷手机时依次发生三件事：

```
刷到广告（曝光）  →  觉得有用点进去（点击）  →  留电话/下单（转化）
   2.78万人              417人                    8人
```

- **曝光**：广告被展示了一次，刷到了就算，不管看没看。
- **点击**：真点进来了。
- **转化**：完成广告主想要的事（留资、加微信、下单，都算）。
- 三层人数一层比一层少，画出来上宽下窄，像漏斗——所以叫**漏斗**。

## 2. 比率与价格（行业缩写，只是"比例"和"单价"）

| 缩写 | 全称 | 一句话意思 | 上图的例子 |
|---|---|---|---|
| CTR | 点击率 | 看到的人里多少比例点了 | 2.78万 × 1.5% = 417 点击 |
| CVR | 转化率 | 点进来的人里多少比例成了 | 417 × 2% = 8 个转化 |
| CPM | 千次展示成本 | 展示 1000 次收多少钱（约 18 元） | 500 元 ÷ 18 × 1000 = 2.78 万曝光 |
| CPC | 单次点击成本 | 每来一个点击收多少钱（约 2.5 元，搜索常用） | — |
| eCPM | 千次展示预期收益 | 平台给广告排队的"含金量分" | 见下节 |

## 3. eCPM 为什么重要（平台怎么发曝光）

平台把曝光给谁？不看出价高低，看"这 1000 次展示能从你身上赚多少"：

- A 出 2 元/点击但没人点 → 1000 次只赚 20 元
- B 出 1 元/点击但人人点 → 1000 次能赚 150 元 → **B 排前面**

`eCPM = 出价 × 预估CTR × 预估CVR × 1000`，所有广告按它排队。
推论：想多拿曝光有两条路——**抬价**，或**把素材做好**（CTR/CVR 高，同样出价排名更靠前）。

## 4. 漏斗演算：正向与逆向

- **正向**（预算→结果）：预算÷CPM×1000＝曝光 → ×CTR＝点击 → ×CVR＝转化。
  例：500 元 ≈ 2.78 万曝光 → 417 点击 → 8 个客人。
- **逆向**（目标→预算）：倒着除回去。要 20 个客人 → 1000 点击 → 6.67 万曝光 → **约 1200 元/天**。

## 5. 统计语言

- **P50（中位数）**：889 个渠道的转化率从小到大排队，站正中间的值＝"典型水平"。
- **P25 / P75**：排在 1/4、3/4 位置的值；P25–P75 之间装着"中间一半"＝**正常区间**。
- **为什么不用平均数**：平均会被极端值拉飞（本项目数据：平均 0.29% vs 中位数 0.02%，差 14 倍，是少数好渠道抬走的）。
- **分组**：按"合作方式 × 广告类型 × 素材类型"把 889 行切成组，每组单独统计。
- **样本量门槛（n≥8）**：组里样本太少统计不出规律，不进主表、只做参考。

## 6. 本项目自己的词（别处查不到）

| 词 | 意思 |
|---|---|
| 曝光端 / 转化端 | 展示、点击、平台收费那一头（CTR/CPM/CPC）＝曝光端；用户进来后成不成交（注册率/订单转化率）＝转化端 |
| 锚点 | 先钉死一个基准数（如 CVR=2%），在它周围加波动生成区间 |
| 基准表 | 02/03/04 三张参数表的总称（见第二部分） |
| 口径说明 | 每张表附的"说明书"：指标怎么定义、数据哪来的、怎么读、什么情况不能用 |
| PASS / FAIL | 校验脚本给每张表的体检结论；FAIL 的数**不得进知识库**，只能修脚本重跑 |
| 出价曲线 | 出价提到基准价 r 倍时，能抢到的曝光/成本变化（出 2 倍价 ≈ 曝光多 60%、成本翻 3.2 倍） |
| 单调性 | 出价↑则曝光↑、成本↑的方向必须成立；自检不过＝数字说胡话，要重算 |

## 7. 平台相关词

| 词 | 意思 |
|---|---|
| 助手 vs 工作流 | 两种产品形态。**复赛只能用"助手"**：流程逻辑全写进提示词；总决赛才有工作流（可视化编排） |
| 系统提示词 | 助手的"出厂程序"：规定先做什么、后做什么、禁说什么 |
| 知识库 / 切片 | 上传文档供助手检索；平台按**标题**把文档切片检索，所以每节标题要写全、每节自包含 |
| 计算器工具 | 助手唯一挂载的工具，所有四则运算都走它，不让模型心算 |
| QA 文档化 | 平台 QA 库不能挂助手 → 把问答写成普通文档放进知识库 |
| 四段式 | 回答的固定结构：结论 → 依据（引哪张表哪条公式）→ 建议 → 风险提示 |
| 节点 | 复赛蓝图的六个固定环节（需求解析→渠道判定→定向→数值预估→自检→方案收尾） |

# 第二部分 · 数据流：从 CSV 到用户答案

## 1. 总图（赛前 → 打包 → 赛中）

```
【数据来源】                 【赛前提炼（脚本，9/10 冻结）】      【比赛当天（对话期）】
889行真实渠道数据  ─脚本─▶  02表 转化端区间 + 流量画像   ─┐
行业常识锚点+倍率  ─脚本─▶  03表 曝光端参数（声明假设）    ├─▶ 基准库 ─┐
数学曲线函数      ─脚本─▶  04表 出价-曝光曲线            ─┘           │
行业公开公式      ─整理─▶  SOP×7 + 系统提示词        ──────────▶ 规则库/提示词 ─┼─▶ 助手
真实问法          ─整理─▶  QA 文档 + 测试集          ──────────▶ QA 库/测试   ─┘    ↓
                                                                     查表 + 计算器实算 + 四段式回答
```

## 2. 三张基准表各是什么

| 表 | 内容 | 数据来源 | 性质 |
|---|---|---|---|
| 02 转化端基准 | 各分组的订单转化率/注册率区间 + 流量画像（UV、停留时长、访问深度、搜索量） | **飞桨真实数据** 889 行统计 | 真实 |
| 03 曝光端基准 | 行业 × 广告类型 × 素材类型的 CTR/CPM/CPC/CVR 区间 | 行业常识锚点 + 倍率合成 | **合成，全声明** |
| 04 出价曲线 | 出价 1.0–3.0 倍 × 曝光/成本/转化倍数 | 数学函数生成 + 单调性校验 | 模型（声明） |

注意：02 与 03 **口径不同、不可互相换算**（02 是历史渠道观测值，03 是行业锚点假设），回答时各引各的表。两表口径详见各自 draft 的"口径说明"。

## 3. 环节（节点）× 数据对照表

| 节点 | 干什么 | 用哪张表/库 | 算什么 | 为什么非算不可 |
|---|---|---|---|---|
| 1 需求解析 | 品类/预算/目标归类 | 规则库（SOP） | 不算数字，只结构化 | 后面查哪张表全由它决定 |
| 2 渠道判定 | 推荐广告形式 | 03 表行情 + 02 表合作方式分布 | 比较 CTR/CPM/CPC | 不比较就推荐＝瞎猜 |
| 3 定向建议 | 投给谁、什么素材 | 02 表流量画像 | 无计算，查区间 | 钱少，买错流量全烧光 |
| 4 数值预估 | 能来多少客/要花多少 | 03 表参数 + 04 曲线 + 计算器 | 正向漏斗 或 逆向反推 | 用户要的就是数 |
| 5 自检 | 核对数字方向 | 04 曲线 + 单调性规则 | 方向核对 | 防模型说胡话 |
| 6 方案收尾 | 预算分配 + 素材建议 | 02/03 表 + SOP 规则 | 分配比例 | 把数变成可执行方案 |
