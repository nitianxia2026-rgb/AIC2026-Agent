## 一、可直接发群的消息

各位，接下来我们不再按“各写一份文档”分散推进，而是分成两条主线，所有工作都要留下可复核证据。

**一、倪天夏 + 陈钰涛：智能体测试与提示词迭代线（主线）**

陈钰涛负责：

1. 用已收集的 70 条真实问法，执行测试集候选题和工具测试题；
2. 每题记录“实际输出、命中的知识库/工具、是否按六节点、是否引用、是否调用计算器、是否触发合规边界、截图”；
3. 重点攻击：缺项追问、跨库混算、没曝光/不出单、敏感行业、违禁词、平台专有词、工具缺参/失败、提示词泄露；
4. 把失败题整理成“问题 → 原因 → 建议修改条款”，不要直接改提示词；
5. 补回真实问法的具体文章/视频 URL（能找回多少补多少）。

我（倪天夏）负责：

1. 在训练平台完成知识库切片、助手配置、计算器和 P0 工具实测；
2. 与陈钰涛一起复盘失败题，决定哪些问题是提示词、知识库、工具参数还是平台限制；
3. 根据证据迭代系统提示词：先形成 v0.2 候选，再做回归测试，最后冻结比赛版；
4. 决定正式比赛添加哪些工具：计算器必挂，Web Research/值得买/图表优先，其他工具通过测试且时间允许再加；
5. 保存平台截图、工具调用记录、模型对比和两次 90 分钟演练结果。

**二、徐毅：真实数据补强线（有条件执行）**

徐毅先不要直接下载大数据或改基准库，按以下顺序做：

1. 先核验 Criteo Sponsored Search Conversion Logs、Criteo Attribution Modeling for Bidding 等候选源的官方页面、许可、字段和规模；
2. 使用现有脚本做最小样本探查，确认字段定义、单位、缺失值和能否映射到我们的五个行业桶；
3. 只有同时满足“来源可追溯、许可可说明、字段可解释、口径不与 KB-01/02/03 冲突”时，才整理为独立参考库或补充基准；
4. 如果不满足，不要硬并入主库，改交一页“不采用原因 + 方法论可借鉴点”；
5. 继续维护飞桨数据和现有脚本流水线，补齐运行日志、抽样手算、文件行数/hash 和数据血缘说明。

## 五、徐毅任务卡：数据处理与外部源筛选

### 先筛选，再处理

候选源优先级：

1. Criteo Sponsored Search Conversion Logs：搜索广告事件链路方法参考；
2. Criteo Attribution Modeling for Bidding：归因、竞价和预算实验参考；
3. 其他 iPinYou/Avazu 等数据：只有找到稳定官方入口和许可后才评估。

不下载 Criteo 1TB 日志，不把匿名特征翻译成人群，不把外部 CTR/CPM 直接写入现有行业基准。

### 数据处理步骤

1. 记录官方 URL、许可条款、下载日期、文件大小、行数、字段和 hash（如允许）。
2. 用 `explore_data.py` 做字段、缺失、范围和分组探查。
3. 能映射到本产品且口径清楚时，使用 `build_benchmark.py` 或新增最小转换脚本生成独立表；不能映射时只输出方法论说明。
4. 使用 `verify_monotonic.py` 和人工抽样检查，不手工改数。
5. 更新《08-数据准备与可追溯说明》，注明“新增/未采用”的决定。
