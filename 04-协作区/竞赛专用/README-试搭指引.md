## 三、搭建顺序（六步）

### 1. 确认环境与回滚基线

- 模拟平台：已有 v0.2 基线只登记助手ID、链接和截图，不覆盖；比赛日平台已清除非知识库操作记录，助手从零新建。
- 检查旧知识库、失败上传任务和重复索引，截图记录后清理会重复召回的旧库；本地源稿一律保留，不使用破坏性回滚。

### 2. 创建唯一主知识库

1. 新建文档知识库：`投手智囊-KB-v3.3-压缩全量`。
2. 只上传材料组#2文件，不上传任何规则库/基准库单文件。
3. 分段策略选"按层级"；若有"切片追加章节标题"，开启。
4. 预览切片：确认 P0-F 出价测试带表格、各章节标题和口径说明没有被拆散。
5. 等待处理状态"可用"。这里只确认上传和切片状态；召回正确性留到独立测试阶段。

若出现容量或 `circuit_breaking_exception/Data too large`，按《全量压缩包上传与回滚说明-v1.md》清理重复索引和失败任务；不要反复上传同一文件。

**比赛日特别**：预上传窗口（9/15–9/18）保留的知识库直接沿用，不重传——v3.3 相对 v3.1 仅四处收敛（新增竞品工具分流），答案口径一致；只有平台确认没有任何保留版本、且重传能在数分钟内完成处理时，才上传#2。

### 3. 创建正式候选助手

1. 新建助手（命名见第二节），完整粘贴材料组#1，不使用平台"自动扩写"。
2. 模型选 Qwen3（登记平台完整显示名），温度取低档；最大历史token保持平台稳定默认值，除非实际测试证明需要调整。
3. 保存后重新打开配置页核对：首部有版本注释行（与材料组#1当前版本一致）和"## 零、硬门"，末尾有"回答质感示例"，即为粘贴完整。
4. 将实际模型、温度、历史token和保存时间写入配置登记第二节。

### 4. 配置开场白与推荐问题

开场白：

```text
你好，我是投手智囊。告诉我你做什么生意、预算和目标，我可以给投放方案、效果测算和出价测试，也能查竞品与官方规则、画漏斗/流程/思维导图，并整理成可复制的Markdown报告。
```

推荐问题：

```text
我开奶茶店，每天预算300元，想让顾客加微信，应该怎么投？
```

```text
帮我搜索3款全自动咖啡机，整理价格、卖点和差异化广告方向。
```

```text
帮我查巨量引擎对食品饮料广告的最新官方准入要求，附链接和日期。
```

```text
餐饮信息流按CPM计费，日预算500元，当前出价20元，目标加微信，目前消耗约60%，应该怎么调？
```

推荐问题只是入口，不附加"不要编造、必须调用"等测试指令。

### 5. 挂载工具

下表是当前项目记录中已确认的完整工具与函数清单。平台显示名称以配置页为准；函数是否随整个MCP一起出现，必须照平台实际登记，不猜测。

| 平台工具/类型 | 已确认函数或能力 | 配置 |
|---|---|---|
| 内置计算器 | 平台显示为“计算器（Python算术）”；内部函数名尚无可靠证据 | 必挂 |
| 内置时间工具 | 平台内置；显示名以配置页为准 | 挂载（提示词已按时间工具规范使用） |
| Web Research | `webSearchPro` | 挂载 |
| 什么值得买 | `product_search_list`、`content_summary_search`、`compare_price` | 三个函数均确认可见后挂载；缺失函数照实登记 |
| 可视化图表 | `generate_funnel_chart`、`generate_line_chart`、`generate_bar_chart` | 三个函数均确认可见后挂载 |
| 思维导图 | `generate_mind_map`、`generate_flow_diagram` | 两个函数均确认可见后挂载 |
| 自定义出价API | `bid_simulate`／`POST /bid-simulate`／`X-API-Key`；已部署 Render | 按材料组#3挂载Schema与密钥；自然问法与降级验证属测试阶段 |

明确不配置：广告平台代投、广告账户API。Markdown报告是文本输出能力，不是工具；不得在工具栏伪造"Markdown生成器"。Word/PDF导出、豆包多模态是否存在以最终配置页为准；没有完成正常/缺参/失败测试前不进入正式能力清单。

自定义API和自定义MCP的具体字段、JSON模板与验收边界见《平台API与MCP挂载说明-v1.md》。REST/OpenAPI服务不得填入MCP配置框冒充MCP Server。

挂载后只核对工具开关、工具显示名和函数列表是否可见并截图。本阶段不发送对话验证工具效果。

### 6. 登记最终配置

## 四、搭建完成条件

全部满足才可标记"搭建完成，待测试"：

- [ ] 正式候选助手可访问，助手ID和链接已登记；
- [ ] 提示词首尾完整，SHA与材料组#1一致；
- [ ] 只挂一个全量知识库，无重复源库；
- [ ] 知识库处理状态为可用，切片预览无明显断裂；
- [ ] 模型、温度和历史token已按实际值登记；
- [ ] 计算器和四类MCP的完整可见函数已登记；
- [ ] 未经平台验证的Word/PDF、文生图和广告账户能力未配置；
- [ ] `bid_simulate` 已挂载且平台解析、鉴权通过；
- [ ] 三类配置截图已保存。

达到此处后停止修改配置，转入《测试集与红队评测模板-v1.md》。任何对话成功或失败都不得回写成"搭建是否完成"；它属于测试结论。

## 五、回滚边界

- 提示词被截断：重新粘贴材料组#1同一源稿，不在平台内临时删句。
- 知识库不可用：比赛日沿用预上传保留版本；模拟平台清理失败任务后重传#2，不改业务内容。
- 自定义API不稳定：立即摘除 `bid_simulate` 即可，提示词已内置 KB-04＋计算器离线兜底，无需改提示词。
- 工具在配置页缺失：登记缺失，不用相近工具冒充。
- 正式测试发现硬失败：保存原回答和截图，回到本地改材料组文件本体→重算SHA→登记，整版覆盖后只回归受影响题。
