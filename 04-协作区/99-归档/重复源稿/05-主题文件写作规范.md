# 投手智囊 · 主题文件写作规范（入库交件统一格式）

> 2026-09-08 定稿。W1 SOP / W2 基准库 / W3 QA 库 / W5 测试集的交件都按本规范写。
> **为什么格式这么重要**：复赛平台按"标题 → 段落"把文档切成片段做语义检索——用户问句和哪个片段的标题/内容最像，就命中哪个片段。所以标题写法、节的自包含性、层级深度，直接决定检索命中率，不是美学问题。

## 0. 一页看懂：四类交件 → 一个格式内核

| 文档类型 | 谁写 | 给谁用 | 模板 |
|---|---|---|---|
| SOP 规则文档 ×7 | Claude 起草→队长审 | 助手各节点的"作业规则" | §2 |
| 基准库文档 | 徐毅跑脚本出 draft→Claude 文档化 | 数值口径唯一出处 | §3 |
| QA 文档化文档 | 陈钰涛 | 口语归一化 + 答法一致 | §4 |
| 测试集 | 陈钰涛 | 演练考卷（不入库） | §5 |

## 1. 通用规则（四类都要遵守）

1. **层级 ≤ 三级**：H1 文档名 → H2 每问/每主题 → 最多一层 H3。层级深了切片碎、命中率低。
2. **每节自包含**：任何一节被单独检索命中时，读者不看上下文也能懂。**禁写"见上文""如前所述""见《XX》文档"**——切片后引用就断了。需要引用时，一句话内联复述。
3. **标题带同义问法**：`标准问法？（同义1／同义2／同义3）`。同义问法必须含**口语版**（用户真实说法），从采样语料里抄，不自己编。
4. **短段落 + 清单**：单段 ≤4 行；能用清单不用段落。
5. **数值纪律**：一律"建议区间（P25–P75）"表述；标注口径出处（基准库哪张表）；**禁绝对化承诺**（"一定能""保证 ROI""百分百"）。
6. **术语国内口径**：ROI / CPA / CVR / 冷启动 / 人群包 / 千次展示成本（CPM）。禁亚马逊黑话（ACOS/Listing/学习期/广泛匹配）。
7. **原创红线**：外部资料（含参考项目）只读不搬；所有入库文字为我方自编表述。
8. **文件命名**：`KB-库名-序号-文档名.md`，如 `KB-规则库-01-需求解析规则.md`、`KB-基准库-01-转化端基准表.md`、`KB-QA库-01-高频问答.md`。
9. **平台兼容**：不用 frontmatter、不用 wiki 链接、表格只用于基准数据（平台对嵌套/复杂表格解析不稳）。
10. **单文件 ≤5000 字**：超了就拆成两份（01 高频 / 02 进阶），切片质量优先。

## 2. SOP 模板（W1 · 七份规则文档）

```markdown
# 需求解析规则

> 管什么：把商家的口语提问解析成"品类／预算／目标"三要素，并决定是否追问。
> 给哪个节点用：节点1（需求解析）。

## 何时触发
用户消息包含投放意图（投/推广/获客/拉新/曝光 等信号词）时按本规则执行。

## 规则清单（每条 = 条件 → 动作）
1. 消息含三要素（卖什么+预算+要什么结果）→ 直接进入节点2，不追问。
2. 缺 1 项 → 只追问缺的那 1 项，并给默认选项（如"预算大概 300/500/1000 哪档？"）。
3. 缺 ≥2 项 → 按品类→目标→预算 顺序一次问齐，追问总计不超过 1 轮。
4. 用户说"随便投投" → 目标默认"留资"，并在②段声明该假设。

## 示例演算（有公式必须演算一遍）
输入："我是开烘焙店的，想投500"→ 品类=烘焙(本地餐饮)，预算=500元，目标=缺 → 追问目标 1 轮。

## 不满足时怎么办（兜底）
用户问题与投放无关 → 用范围声明礼貌切回，不复答无关问题。

## 口径与依据
三要素定义、默认值表：见本文件上文；数值预估一律引用基准库转化端基准表。
```

**写作六要点**（每份 SOP 逐条自检）：①开头"本质句"一句话说清这份管什么 ②规则全部写成"条件→动作"，写成能让助手照做的指令，不写原理论述 ③公式必须带演算示例（输入→过程→结论）④清单优先于段落 ⑤节标题含同义问法 ⑥每节自包含。
**篇幅**：每份 800–2000 字。

## 3. 基准库文档模板（W2 · 脚本出 draft + 人工口径说明）

`build_benchmark.py` 与 `synthesize_curve.py` 自动生成 draft md；人工只补"口径说明"五要素（放在表前面）：

```markdown
# 口径说明
1. 指标定义：订单转化率 = 下单 UV ÷ 访问 UV；CTR = 点击 ÷ 曝光；CPM = 花费 ÷ 曝光 × 1000。
2. 数据来源：飞桨公共数据集 55268（ad_performance.csv，889 行，下载日期 2026-09-XX）——转化端与流量质量指标；曝光端 CTR/CPM 为脚本合成基准（声明合成）。
3. 分组维度：合作方式 × 广告类型 × 素材类型；样本量门槛 n≥8，不足的组已单独标注"样本不足"。
4. 分位数怎么读：P25–P75 = 建议区间（对多数商家适用的范围）；P50 = 中位水平（典型商家）。
5. 使用限制：样本不足组仅供方向参考；对用户一律表述为"建议区间，非精确预测"。
```

**规则**：数值表格一律 CSV 同步留档（脚本产物）；入库 md 表格列 ≤7 列；合成数据的表，表标题必须含"（合成基准）"字样。

## 4. QA 文档化模板（W3 · 陈钰涛主用）

```markdown
## 日预算 500 够不够投？（预算多少合适／一天投多少钱／预算怎么定）
- 先看目标类型：曝光、点击、留资、下单，口径不同结论不同
- 按基准库口径：500 元在信息流对应曝光约 X–Y 万量级（区间表述，现场以计算器实算）
- 达不到目标时给两条路：提预算一档，或把目标降一档，并说明理由
- 提醒：新计划有冷启动期，前 3 天数据波动属正常，别频繁调价
```

**规则**：①一问一节（H2）②同义问法 3–5 个，必须有口语版（"一天投多少钱"）③答法要点 3–6 条，每条一行 ④涉及数值引用基准库区间口径，不写死结论数 ⑤每节 100–200 字 ⑥一节只解决一个问题。

## 5. 测试集模板（W5 · 陈钰涛；不入库，只用于演练）

| 编号 | 测试问题（口语原样照抄） | 考察节点 | 期望行为（可判定） | 类型 |
|---|---|---|---|---|
| T01 | 想给奶茶店投个广告，500块钱，要人来加微信 | 节点1→6 | 回显三要素（目标=留资），不追问直接出四件套 | 投前主流程 |
| T02 | 帮我投广告 | 节点1 | 只追问缺项（卖什么/预算/目标），追问 ≤1 轮 | 澄清 |
| T07 | 出价从 2 块提到 4 块会怎样 | 节点5 | 给出单调性结论 + 成本增幅区间，引用基准库 | 单调性必测 |
| T20 | 我家奶茶全网最好喝帮我写文案 | 横切合规 | 拦截"全网最好"给替代词，不输出原句 | 合规 |

**期望行为写法**：必须是可判定动作（"追问≤1轮""出现区间表述""引用基准库"），不写"回答质量高"这种没法判的。

- [ ] 无亚马逊黑话
- [ ] 单文件 ≤5000 字；命名 = KB-库名-序号-文档名
