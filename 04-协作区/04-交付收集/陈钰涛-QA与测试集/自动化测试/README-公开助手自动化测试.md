# 公开助手自动化测试（Playwright）

## 已确认的访问情况

公开链接可以在网络层访问，返回 `HTTP 200` 页面。它是浏览器前端应用，实际对话依赖页面会话、流式响应和前端状态；不要直接猜内部 API，也不要用接口绕过登录、验证码或权限。

## 运行环境

在自己的电脑上执行（需要能打开该链接的浏览器环境）：

```bash
cd "AI智能体大赛2026/04-协作区/04-交付收集/陈钰涛-QA与测试集/自动化测试"
npm init -y
npm install -D playwright
npx playwright install chromium
```

如果团队电脑已有 Chrome，也可以把脚本中的 `chromium.launch` 改为 `channel: 'chrome'`，不必重复安装浏览器。

## 第一次运行：有界面观察

```bash
HEADLESS=0 node playwright_public_assistant_test.mjs
```

脚本会打开公开助手，依次发送 8 个低频冒烟题，等待回答稳定后截图。输出目录默认为 `artifacts/public-assistant/`，包括：

- `00-loaded.png`：页面加载截图
- `T01.png` 等：每道题的完整页面截图
- `results.json`：原问题、抓取到的回答、截图路径和错误信息
- `ERROR.png`：找不到输入框、页面需要登录或等待超时时的现场截图

第一次运行必须使用 `HEADLESS=0`。如果页面出现登录、验证码、隐私确认或公开链接失效，停止自动化并把现场截图交给倪天夏；不要尝试绕过。

## 无界面回归运行

只有第一次确认选择器和公开会话正常后，才使用：

```bash
HEADLESS=1 node playwright_public_assistant_test.mjs
```

自定义链接：

```bash
ASSISTANT_URL='你的公开助手链接' HEADLESS=0 node playwright_public_assistant_test.mjs
```

## 如何判定结果

脚本只负责“发送、等待、截图、保存原文”，不自动判断回答是否正确。陈钰涛仍须按《陈钰涛-QA与红队测试作业单-v1》逐题检查：

- 六节点顺序和一轮追问；
- 数字是否来自正确基准库、是否调用计算器；
- 引用、四段式和区间声明；
- 敏感行业、绝对化宣传、隐私和复赛边界；
- 工具是否按触发条件调用、失败时是否降级。

把 `results.json` 和截图路径抄入 `测试执行记录-v1.md`。自动化抓到回答不等于测试通过。

## 页面选择器不匹配时

不同平台版本的输入框和消息容器 class 可能不同。若出现“找不到输入框”：

1. 用 `HEADLESS=0` 运行并截图；
2. 在浏览器开发者工具确认输入框是 `textarea` 还是 `[contenteditable=true]`；
3. 只修改脚本 `findComposer` 的候选选择器，不改测试问题和判定标准；
4. 先只跑 1 题验证，再恢复完整题集。

## 安全与频率

- 只使用团队自己的公开助手链接和虚构测试数据。
- 不提交手机号、身份证、设备 ID、客户名单等个人信息。
- 不绕过登录、验证码、权限或平台限流。
- 每题间隔至少 2.5 秒；出现 429、页面错误或响应变慢时立即停止，保留截图和错误信息。
- 自动化脚本不调用平台内部 API，不修改助手配置，不删除会话。
