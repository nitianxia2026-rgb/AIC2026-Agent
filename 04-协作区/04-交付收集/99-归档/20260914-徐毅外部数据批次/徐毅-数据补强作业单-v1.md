# 徐毅 · 数据补强作业单

> 版本：v1.0｜日期：2026-09-12｜负责人：徐毅｜协作人：倪天夏
> 目标：在不破坏现有基准库口径的前提下，核验外部真实数据是否值得补充，并把可复核的数据证据交给队长。

## 0. 先看结论：你这次不是“数据越多越好”

本项目当前主库已经固定为：

- KB-基准库-01：飞桨真实历史数据，负责转化端和流量质量观察；
- KB-基准库-02：项目合成曝光端基准，负责 CTR/CPM/CPC/CVR 演算；
- KB-基准库-03：项目合成出价曲线，负责出价倍数和单调性解释。

外部数据只有在“来源、许可、字段、行业映射、口径”都说得清时，才可能补充。否则交“不采用原因 + 方法论可借鉴点”，不要为了增加数据量强行并入 KB-01/02/03。

## 2. 任务总流程

```text
记录来源与许可
  ↓
下载/保存最小样本（或只读官方说明）
  ↓
字段探查：字段、单位、缺失、粒度、匿名化
  ↓
行业映射判定：直接 / 可解释代理 / 无法映射 / 不确定
  ↓
口径冲突检查：与 KB-01/02/03 是否重复或混算
  ↓
三选一：独立参考库 / 补充基准候选 / 不采用
  ↓
交付来源表、探查报告、运行日志、最终建议
```

你必须按顺序完成，不能下载后直接生成基准表。

## 4. 第二步：文件和脚本操作

### 4.1 先保存原始文件，不在原文件上修改

目录建议：

```text
04-交付收集/徐毅-基准库/
├── raw_external/                 ← 原始压缩包/原始 CSV，只读保存
├── staging_external/             ← 只放探查用最小样本或字段映射副本
├── 外部数据源筛选-v1.md
├── 外部数据探查-v1.md
├── 外部数据入库建议-v1.md
└── 数据质量与可追溯补充-v1.md
```

如果数据很大，只取前 1,000–10,000 行做字段探查，并在报告中写清“仅为探查样本，不用于生成基准”。不要把抽样文件冒充完整数据集。

### 4.2 记录文件证据（macOS 终端）

在原始文件所在目录执行：

```bash
wc -l 文件名.csv
du -h 文件名.csv
shasum -a 256 文件名.csv
python3 --version
date '+%Y-%m-%d %H:%M:%S %z'
```

压缩包也执行一次 `shasum -a 256 文件名.zip`。把命令和输出复制到 `数据质量与可追溯补充-v1.md`，不要只写一个“已检查”。

### 4.3 运行现有探查脚本

现有脚本只能直接识别与飞桨数据相近的字段。所有命令在 `04-协作区/03-数据脚本/` 下执行：

```bash
python3 explore_data.py
```

如果外部 CSV 字段不同：

1. 不改原始文件；
2. 复制到 `staging_external/`；
3. 在 `explore_data.py` 顶部 `INPUT_CSV` 指向副本；
4. 仅在 `ALIASES` 中增加“同义列名”，不改变计算逻辑；
5. 运行后把修改过的别名和命令记录下来。

如果外部数据没有“合作方式/广告类型/素材类型”等字段，脚本可以用于基本字段探查，但不能直接运行 `build_benchmark.py` 生成项目主库。此时交“方法参考”或“独立样本库候选”。

## 5. 第三步：字段判定——每个字段都要回答 6 个问题

在 `外部数据探查-v1.md` 中逐字段填写：

| 问题 | 合格标准 |
|---|---|
| 字段名是什么 | 写原始字段名和中文解释 |
| 记录粒度是什么 | 曝光级、点击级、用户级、广告计划级或日级；不清楚则不合格 |
| 单位是什么 | 元、次、百分比、小数、秒等；不能靠猜 |
| 分母是什么 | CTR 的曝光数、CVR 的点击数、CPA 的转化数必须明确 |
| 缺失/异常如何处理 | 空值、0、负数、极端值分别统计；不直接删除 |
| 是否匿名 | 匿名 ID 只能当 ID，不得翻译成兴趣、人群或行业 |

### 5.1 可用于广告指标的字段组合

只有同时满足分母清楚、单位清楚、粒度可聚合，才允许计算：

- CTR = 点击数 ÷ 曝光数；
- CPM = 花费 ÷ 曝光数 × 1000；
- CPC = 花费 ÷ 点击数；
- CVR = 转化数 ÷ 点击数；
- CPA = 花费 ÷ 转化数。

缺少曝光、点击、花费或转化中的任一关键字段时，不得补造指标，也不得用匿名特征替代。

### 5.2 外部数据与现有三库的关系

| 外部数据能提供什么 | 可以做什么 | 不可以做什么 |
|---|---|---|
| 搜索曝光/点击/转化事件 | 写搜索广告事件链路方法参考 | 直接改写成五行业 CPC/CVR 行情 |
| 竞价、归因、反事实字段 | 写竞价/实验 SOP 的参考说明 | 覆盖 KB-03 合成出价曲线 |
| 匿名 CTR 标签 | 说明 CTR 建模字段和限制 | 翻译成具体人群画像或行业效果 |
| 真实花费和曝光 | 若行业、时间、平台口径都清楚，可做独立样本表 | 与 KB-02 合成 CPM/CTR 跨表拼接 |

## 6. 第四步：行业映射——不再凭感觉判断

项目五个行业桶固定为：餐饮美食、教育培训、电商零售、本地服务、家居建材。

### 6.1 四种映射结果

| 判定 | 什么时候可以这样判 | 后续处理 |
|---|---|---|
| **直接映射** | 原始字段明确给出行业/品类，且能逐条写出归类规则；例如“餐饮/咖啡/烘焙”→餐饮美食 | 可进入“补充基准候选”，仍需样本和口径验收 |
| **可解释代理** | 外部有公开分类，但不是本项目五桶；能写映射表但存在业务偏差 | 只能做独立参考，不进入主库演算 |
| **无法映射** | 只有匿名 feature、user_id、ad_id、点击标签，没有行业/品类语义 | 只能做方法论参考 |
| **不确定** | 同一值可能属于多个行业，或字段说明不足 | 暂停计算，向队长报告，不自行归类 |

### 6.2 映射证据要求

每个直接映射必须提供：

1. 原始字段名；
2. 原始取值示例；
3. 映射规则表；
4. 至少 20 条人工抽样记录；
5. 误分/无法判断数量；
6. 队长复核结论。

**特别说明：** Criteo 的匿名用户/广告特征通常不能映射到五个行业桶。即使模型可以预测点击，也不能把某个 feature 值解释成“教育人群”或“餐饮用户”。

## 7. 第五步：准入评分和三种结果

对每个候选数据源按 10 分制打分：

| 维度 | 分值 | 5 分标准 |
|---|---:|---|
| 来源可追溯 | 0–2 | 官方页面、文件名、日期、hash 齐全 |
| 许可可说明 | 0–2 | 有许可页并能摘录允许用途 |
| 字段可解释 | 0–2 | 粒度、单位、分母、缺失处理清楚 |
| 五行业映射 | 0–2 | 有直接字段和抽样映射证据 |
| 口径不冲突 | 0–2 | 能与 KB-01/02/03 分库，不跨表混算 |

### 7.1 三种分流

- **补充基准候选：8–10 分**，且“来源、许可、字段”三项不能为 0；行业映射至少 1 分；先生成独立 CSV/MD，不能直接覆盖主库。
- **独立参考库：5–7 分**，或行业映射为 0 但方法论价值高；只回答数据字段、事件链路、竞价/归因方法。
- **不采用：0–4 分**，或许可不明、字段无法解释、来源不可追溯；交不采用原因，不继续处理。

“补充基准候选”不等于最终入库。队长还要检查样本量、分组稳定性、切片质量和平台挂载限制。

## 8. 第六步：样本和质量门槛

以下是项目内部筛选门槛，不是行业标准；达不到就降级，不要补数字：

1. 以广告计划×日期或其他可解释聚合粒度作为一行，不能直接把数十亿事件当作独立样本数。
2. 每个拟入库分组至少 30 行可解释聚合记录；少于 30 行只作方向参考。
3. CTR/CVR 的分母必须大于 0；花费、曝光、点击、转化不得出现无法解释的负数。
4. 每个指标报告缺失率、0 值比例、P25/P50/P75 和极端值处理方法。
5. 同一来源的时间、地区、平台和计费方式必须保持一致；混合后不能声称是统一基准。
6. 外部数据与 KB-02 的合成参数同时存在时，分开建表、分开引用，禁止取平均或拼接区间。
