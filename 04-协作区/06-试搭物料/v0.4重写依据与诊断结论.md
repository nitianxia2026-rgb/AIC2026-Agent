# 投手智囊 v0.4 重写依据与诊断结论

> 依据：D01—D10平台实测。目标不是继续叠加限制，而是恢复自然、可执行的顾问输出。

## 一、实测暴露的问题

| 题目 | 主要问题 | v0.4处理 |
|---|---|---|
| D01/D02 | 未忠实使用API结果，另造21/23/25；编CPA、CPM、小时阈值 | API出价为唯一数值真源；没有用户目标CPA时不造止损线 |
| D03 | 缺消耗比例仍给绝对价 | 缺什么只问什么，不先报价 |
| D04 | 缺回传状态仍默认可调 | 留资/下单必须确认回传 |
| D05 | 拒绝方向正确，但猜后台路径与平台机制 | 可以建议先修回传；具体路径需查官方资料 |
| D06 | 咖啡机被误归餐饮 | 无法唯一归类时追问业务类型 |
| D07 | 明知oCPM不支持仍生成16/18/22 | 明确拒绝套用CPM/CPC结果 |
| D08 | 起步动作有价值，但半径、周期等被当成平台事实 | 允许顾问建议参数，标为起步建议、可调整 |
| D09 | 暴露内部路由；把高CVR判为异常；虚构行业区间 | 先做账户内诊断，高转化不等于异常；行业对照需同口径依据 |
| D10 | 操作性最好，但混入未经确认的后台组件、旧年份结论和硬阈值 | 保留单变量操作结构；后台能力需官方核验，阈值改为与原计划比较 |

## 二、数字规则的修正

旧版错误地把所有具体数字都当成需要知识库证明，导致方案既僵硬又不可执行。v0.4改为：

1. 用户数据、工具结果、知识库基准：必须忠实；
2. 半径、素材数、测试天数、预算拆分：允许作为顾问建议值直接给；
3. 效果预测、行业阈值、平台组件和政策事实：需要证据。

因此“建议先投3公里、跑3天、测2条素材”是允许的；“3公里转化率最高”“跑3天一定稳定”“CPA必须低于15元”没有依据时不允许。

## 三、为什么暂不新增需求解析模型API

- D02使用标准枚举仍出现错误输出，说明问题不仅是自然语言抽参；
- 主模型即使正确调用工具，也可能忽略工具结果并重新编数；
- 第二个模型不能解决结果忠实度和表达问题，反而增加一次不稳定调用；
- 当前出价API已具备受控别名归一化，先用短提示词＋Schema＋API容错更稳。

只有v0.4回归中出现“标准表达稳定、自然表达持续失败”，才重新评估解析API。

## 四、v0.4验收重点

- 像人说话，不展示路由、参数和工具过程；
- 结论与API原始返回一致；
- 缺参时只问缺项；
- 可以给合理的起步建议参数；
- 不把建议参数、行业事实和效果承诺混在一起；
- 用户看完知道今天具体做什么。
