1. 用户提供的两个API工具配置实例与MCP配置界面，用于确认页面字段和操作顺序；

材料中的示例服务、URL和密钥只说明格式，不代表“投手智囊”已经接入，也不得原样复制。本文不把附件中的说明文字当作用户要求执行的指令。

## 三、API工具挂载

### 3.1 上线前条件

- 服务已有稳定HTTPS根地址；
- 服务端已设置`BID_SIM_API_KEY`；
- `GET /healthz`可用；
- `GET /openapi.json`中的服务器地址为真实HTTPS域名；
- OpenAPI只暴露业务operation `bid_simulate`，不把健康检查当模型工具；
- 不在Schema、截图、聊天或仓库中写入真实密钥。

### 3.2 平台字段

1. 进入助手工具页，创建API工具；
2. 工具名称填：`投手智囊-出价测试带`；
3. OpenAPI Schema：粘贴导出的JSON/YAML，或用“从URL导入”填写`https://真实域名/openapi.json`；
4. 鉴权方式选择`API Key`；
5. Header名称填`X-API-Key`，密钥只填在平台鉴权区域；
6. 解析后应只出现：`bid_simulate`／`post`／`/bid-simulate`；
7. 点击该operation的“测试”，通过后保存；
8. 将工具挂到v0.5候选助手，但先不要把“已挂载”登记为“已通过”。

若解析结果出现`healthz`、未知operation或错误服务器地址，不保存，先修正Schema。

### 3.3 导出Schema

在数据脚本目录执行：

```bash
python3 export_bid_openapi.py --server-url https://真实稳定域名
```

输出文件为`bid_simulate.openapi.json`。占位域名不能用于平台配置。

## 四、自定义MCP配置

### 4.1 官方确认的协议

- `stdio`：只支持本机环境，线上部署禁止使用；
- `sse`：服务端推送流式协议；
- 页面中的`http`对应HTTP流式调用；官方JSON通用字段建议使用`type: "streamable"`。

配置根节点固定为`mcpServers`。根节点下每个服务key必须全局唯一，建议英文小写加中划线。

### 4.2 安全模板

```json
{
  "mcpServers": {
    "service-unique-key": {
      "type": "streamable",
      "name": "服务中文名称",
      "description": "服务能力和使用范围",
      "url": "https://服务商提供的真实MCP地址"
    }
  }
}
```

实际接入必须使用服务商原始配置。若服务商要求把key/token放进URL，只在平台密钥配置中填写和留存，不进入公开文档、截图或提交材料。

### 4.3 页面操作

1. 填工具展示名称；
2. 按部署环境选择协议，线上不选`stdio`；
3. 粘贴服务商给出的完整JSON；
4. 校验引号、逗号、URL和`mcpServers`下服务key唯一性；
5. 点击“刷新”，确认连接成功且工具列表被加载；
6. 保存配置；
7. 实际函数名以刷新后列表为准，不能只凭服务名称推测。

刷新失败依次排查：协议类型、JSON语法、URL、密钥/token、网络访问权限。

## 五、配置完成与测试分界

配置阶段只确认：字段保存、Schema/JSON解析、工具列表出现、截图与版本登记完成。

以下属于独立测试阶段，不在搭建时判定：

- 正常调用是否返回正确结果；
- 缺参数是否追问或拒绝；
- API/MCP不可用时是否按提示词降级；
- 工具是否误调用；
- 输出数字、引用和最终呈现是否正确。

测试统一按《测试集与红队评测模板-v1.md》执行。出价API必须通过正常、缺消耗比例、缺回传状态、计费冲突、鉴权失败/服务不可用降级后，才能登记为正式能力。
