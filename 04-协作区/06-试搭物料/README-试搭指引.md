# 投手智囊 · 竞赛平台试搭指南

> 版本：v2.0｜更新：2026-09-16｜操作人：倪天夏
>
> 当前目标：在平台保留 v0.1 基线，同时建立只更换系统提示词的 v0.2 候选，用于13组阻断题回归。
>
> 当前不接入：未验收的出价仿真算法、KB-04、规则08、自动代投或广告平台 API。

## 一、今天搭完后应该有什么

平台中应保留两个可区分、可回滚的助手：

| 助手 | 用途 | 唯一差异 |
|---|---|---|
| `投手智囊-v0.1-baseline` | 保存旧版基线，供后续A/B对照 | 使用 `系统提示词-v0.1.md` |
| `投手智囊-v0.2-candidate` | 当前回归测试对象 | 使用 `系统提示词-v0.2-交互候选.md` |

两者的模型、温度、知识库、工具和其他平台配置必须相同。当前只测试 v0.2，不删除或覆盖 v0.1。

## 二、开始前准备

打开以下三个本地文件：

1. 系统提示词：`系统提示词-v0.2-交互候选.md`；
2. 知识库上传文件：`KB-投手智囊-全量优先级压缩上传包-v1.md`；
3. 配置登记表：`../04-交付收集/01-倪天夏-队长与平台/平台配置与版本记录-v1.md`。

先在平台确认 v0.1 助手是否仍可访问。若没有 v0.1，就先按本指南搭一个基线；若已有，优先复制它生成 v0.2，以减少配置差异。

## 三、步骤1：建立唯一主知识库

### 3.1 上传前清理

在平台知识库列表中检查旧的规则库01–07、基准库01–03、QA库、失败上传任务和重复版本。

- 本轮平台只使用一个合并知识库；
- 旧库先截图记录名称和版本，再删除平台中的重复索引或失败任务；
- 不删除本地源稿；
- 不同时挂载“全量压缩包”和它所包含的单库，否则会重复召回并占用容量。

若仍出现 `429 circuit_breaking_exception`，按 `全量压缩包上传与回滚说明-v1.md` 清理平台历史索引，释放空间后再传；反复上传同一文件不会解决该错误。

### 3.2 创建并上传

1. 新建文档知识库，名称建议：`投手智囊-KB-v1-压缩全量`。
2. 只上传：`KB-投手智囊-全量优先级压缩上传包-v1.md`。
3. 分段策略优先选择“按层级”。
4. 若平台提供“切片追加章节标题”，开启。
5. 预览切片，确认标题与正文在同一切片，表格没有从关键行中间断开。
6. 完成数据处理，等待状态变为可用后再挂载助手。

### 3.3 五项检索验收

在知识库检索或助手测试中依次查询以下短语：

1. `oCPM 不等于按成交付费`
2. `固定预算加价不保证曝光倍增`
3. `时段没有小时数据`
4. `全网最低`
5. `70/30 不是行业保证`

每项应能命中相关规则。任一项完全无结果，先检查切片和索引，不进入助手测试。

## 四、步骤2：保留或补建 v0.1 基线

如果平台已有可用的 v0.1，核对后直接进入下一步；没有才新建。

| 配置项 | v0.1要求 |
|---|---|
| 名称 | `投手智囊-v0.1-baseline` |
| 系统提示词 | 完整粘贴 `系统提示词-v0.1.md` 正文 |
| 模型 | 优先使用当前已验证模型；建议 `deepseek-v3.1` |
| 温度 | 选平台允许的低档，建议 0.1–0.3；记录实际值 |
| 知识库 | 只挂 `投手智囊-KB-v1-压缩全量` |
| 必挂工具 | 计算器 |
| MCP | 与 v0.2 完全一致，只挂已实测可用项 |

保存后发一句“我想投广告”，确认助手能正常回应。把助手 ID/链接、配置页和工具页截图记录到平台配置表。

## 五、步骤3：复制并配置 v0.2 候选

1. 优先使用平台的“复制/克隆助手”功能复制 v0.1；没有复制功能时手动新建。
2. 名称改为 `投手智囊-v0.2-candidate-20260916`。
3. 删除提示词输入框中的旧内容，完整粘贴 `系统提示词-v0.2-交互候选.md` 正文。
4. 不使用平台的“自动扩写提示词”；如果误点后内容发生变化，重新粘贴源稿。
5. 核对模型、温度、知识库和工具，必须与 v0.1 相同。
6. 保存并重新打开配置页，确认长提示词没有被截断；重点搜索末尾“合规、隐私与能力红线”。
7. 记录助手 ID/公开链接、保存时间和配置截图。

提示词文件开头的版本说明可以保留。不得把尚未完成的出价仿真内容临时手写进平台提示词；算法验收后另建 v0.3。

## 六、步骤4：设置开场白和推荐问题

当前阶段以回归为主，两版必须使用相同内容，避免影响A/B测试。

### 开场白

```text
你好，我是投手智囊。告诉我你做什么生意、准备投多少预算（每天还是总预算）以及想获得曝光、点击、加微信还是成交，我会先给你能执行的投放建议；需要时还可以帮你查竞品、画投放图或整理方案。
```

### 推荐问题

```text
我开奶茶店，每天300元，想让顾客加微信，应该怎么投？
```

```text
我的广告有点击但没人咨询，应该先检查什么？
```

```text
帮我比较信息流和搜索广告，哪个更适合小预算？
```

```text
我想了解提高出价会发生什么，需要提供哪些数据？
```

当前不要加入“自动给出最佳出价”等算法已经上线的表述。

## 七、步骤5：配置工具

### 7.1 必挂

- 计算器：开启；用于乘除、比例、区间端点和单位换算。

### 7.2 推荐挂载但必须实测

| 工具 | 所需函数/能力 | 测试通过后用途 |
|---|---|---|
| Web Research | `webSearchPro` | 最新官方政策、平台规则和公开资料 |
| 值得买 | `product_search_list`、`content_summary_search` | 用户明确要求时做商品/竞品观察 |
| 可视化图表 | 漏斗图、折线图、柱状图 | 用户明确要求把已有数据画图 |
| 思维导图 | 流程图、思维导图 | 用户明确要求解释流程或方案结构 |

Word/PDF导出和文生图可暂不挂；只有时间允许且完成正常、缺参、失败三类测试后再添加。自建 API 本轮不接。

### 7.3 每个工具的最小验收

对准备正式保留的每个 MCP，至少验证：

1. 正常输入能返回有效结果；
2. 缺参数时会追问或明确失败，不编结果；
3. 空结果/超时时能降级为文字说明；
4. 图表或图片工具返回链接后，助手会把图片直接展示，而不是只留下中间链接；无法展示时会保留链接并给文字版。

出现误调用、持续超时、只给裸链接或结果不可追溯时，先摘除该工具，不让它进入回归关键路径。

## 九、步骤7：三题冒烟检查

先在 v0.2 中每题新建会话：

| 题目 | 必须看到的行为 |
|---|---|
| `我想投广告` | 一次问齐行业、预算及周期、目标；不直接给效果数字 |
| `想给奶茶店投广告，500块，要人加微信` | 先确认500元是日预算还是总预算/投几天；不擅自按7天计算 |
| `出价从2块提到4块会怎样` | 先确认预算、计费方式和观察结果；不把理论曲线说成实际转化增幅 |

如出现以下任一情况，暂停正式回归并保存回答原文：

- 缺参数仍输出曝光、点击、转化或预算数字；
- 引用不存在的知识库数据；
- 把合成曲线称为真实平台预测或个性化算法；
- 未调用计算器却直接完成业务算术；
- 工具空结果后编造商品、价格或政策。

## 十一、问题怎么处理

| 现象 | 处理 |
|---|---|
| 提示词粘贴后被截断 | 保存后重新打开检查；缩短前先保留原稿和截图 |
| 知识库429/容量超限 | 清理重复索引和失败任务，只保留全量压缩包 |
| 知识命中错误 | 保存问法、回答和命中片段，不直接乱改源库 |
| 数字无来源或跨库混算 | 记录题号并暂停该题通过判定 |
| MCP超时或空结果 | 检查是否按提示词降级；未降级则记录失败并暂时摘除 |
| 图片只返回链接 | 检查提示词是否完整；要求直接展示，仍失败则保存链接和文字版 |
| 两版配置不一致 | 先修正配置，再重新测试；旧回答不能用于A/B结论 |

不要在平台里边测边随手改提示词。发现问题先保存原始回答，由 Codex 判定后修改本地源稿，再整版替换并只回归受影响题。

全部满足后，P0-01才可标为完成并进入稳定回归：

- [ ] v0.1基线仍可访问；
- [ ] v0.2候选已创建，提示词首尾完整；
- [ ] 两版除提示词外配置一致；
- [ ] 只挂一个全量压缩知识库，无重复源库；
- [ ] 五项知识检索均有正确命中；
- [ ] 计算器可用，MCP清单已记录；
- [ ] 三题冒烟没有阻断错误；
- [ ] 平台配置表和截图已补齐；
- [ ] v0.2链接/ID已交给陈钰涛。

出价仿真脚本即使并行完成，也必须先通过自动校验、两组手算和队长验收；通过后另建 v0.3 候选，不覆盖当前 v0.2 测试证据。
